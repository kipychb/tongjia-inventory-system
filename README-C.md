# 統家自動補貨系統 — C 組：店長操作介面

把 A 組（需求預測、補貨計算）與 B 組（異常偵測、風險審核）整合成店長可以直接操作的網頁系統。
純 HTML／CSS／JavaScript，沒有第三方套件，只需要 Node.js 18 以上。

## 啟動

```bash
npm start
```

開啟 <http://localhost:3000/app/>（或執行 `node server.mjs`）。
不能直接雙擊 `index.html`，因為瀏覽器不允許 `file://` 載入模組與 `sales_data.json`。

## 測試

```bash
npm test
```

會跑全部 A、B1、B2 與 C 組的測試（`node --test`）。

## 資料流程

```text
sales_data.json + 商品主檔
  → A2 predictDemandFromSalesData（移動平均 × 假日／促銷倍率）
  → B2 prepareEventDemandAdjustment（預測日期內的特殊事件加入需求）
  → A1 calculateReorderQuantity（補到目標庫存，依最低訂購量／倍數取整）
  → 店長輸入訂貨量
  → B1 checkReplenishmentResult（手誤防呆、偏離建議量）
  → B2 assessB2（極端數量、容量、效期、特殊事件）
  → 店長確認 / 主管審核（decideB2）
  → 送單前重新計算 → 產生補貨單與 createB2AuditRecord 審核紀錄
```

## 畫面功能

1. **今日補貨**：選預測日期、假日、促銷；表格列出現有庫存、在途、預測需求、安全庫存、系統建議與可修改的訂貨量，每列即時顯示風險狀態。
2. **明細側欄**：歷史銷售長條圖（標出 A2 採用的 3 筆與活動日）、逐步計算過程、B1/B2 檢查結果、店長確認或主管審核。
3. **特殊事件登錄**：登錄演唱會、團購等額外需求，系統重新計算建議量。
4. **補貨單**：所有品項正常或已確認後才能產生；預覽後模擬送交統家總部，紀錄保存在瀏覽器 localStorage。
5. **補貨模型說明**：定期盤點 (R, S) 模式、移動平均預測、安全庫存與風險門檻，可直接用於教學影片。

## 狀態規則

| 狀態 | 條件 | 店長要做的事 |
| --- | --- | --- |
| 正常 | B2 `normal` | 不需處理 |
| 待店長確認 | B2 `warning` | 選原因＋補充說明（≥5 字）後確認 |
| 待主管審核 | B2 `high` | 改回建議量，或由區督導審核（需主管編號） |
| 資料錯誤 | B2 `blocked` | 修正訂貨量格式 |

確認紀錄綁定當時的數量；之後修改數量，確認就會失效，需要重新確認。

## 原型假設與限制

- 預測期間為「一天」：便利店每日訂貨、隔天到貨，預測需求等於下一個到貨日的需求。
- B2 的「到貨時預估庫存」以目前庫存位置（現有＋在途－欠貨）保守估計。
- P003 以後的商品、庫存、容量與效期是 C 組模擬值，非統家實際資料。
- 身分切換、主管編號與送單都是模擬；沒有登入驗證、資料庫或真正的總部 API。
